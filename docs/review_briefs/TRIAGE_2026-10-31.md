# Review-brief triage: docs/review_briefs/ against dev @ 0b501108 (2026-10-31)

Read-only triage for docs/RELEASE_READINESS.md "Open crash, data-loss and security items" item 4.
All 38 files under docs/review_briefs/ were covered. Code was located by symbol, so a brief's own
line numbers were ignored. Every line reference below is to the current dev tree, and fixing
commits come from `git log -S/-G` on a distinctive token of the fix. Nothing was built or run.

Status meanings: FIXED (current code cited), GONE (the code no longer exists), STILL-OPEN (current
defective code plus a concrete failure), NOT-A-BUG (with the reason), NEEDS-RUNTIME (with the test
that would settle it).

Every finding in every brief was triaged, including items a brief had already marked [x] or
RESOLVED. Those claims were re-checked against current code, more lightly. The MCP stdio-session
brief is a 4.7k-line quality ledger with no per-finding severities: its three original-review
findings and the open items its prose names were triaged, and their severity follows the ledger
priority (critical = HIGH, normal = MEDIUM). Its individual acceptance rows were not re-verified.
The partition live-certifier brief is a certification design and evidence log, and its two [x]
defects are counted. Nine briefs say NO FINDINGS.

Count note: the readiness doc says "78 unverified findings (18 HIGH) in 14 briefs". Counting
every unchecked item gives 99 findings across 20 briefs, so the doc probably excluded briefs that a
ledger unit binds. The totals below cover all 140 items, checked and unchecked.
